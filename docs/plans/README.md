# Plans

Plans are bounded execution documents, not permanent architecture records.

A plan should state:

- the intended outcome and non-goals;
- affected contracts and packages;
- ordered implementation steps;
- verification and documentation updates;
- unresolved decisions and risks.

When work completes, preserve durable conclusions in code, reference docs,
knowledge records, or ADRs. Completed plans may then be archived under a future
documented convention rather than becoming an accidental source of truth.
