# ADR 0008 tool proof implementation plan

**Goal:** Produce reproducible evidence for the agreed ADR 0008 semantics.
**Status:** Complete; ADR 0008 subsequently accepted by the maintainer
**Spec:** [Tool execution contract](../design/tool-execution-contract.md)
**Architecture:** One retained gateway implementation, a shared conformance
suite, and an MCP adapter. Provider-private metadata binds calls to an exact
operation; the gateway never reads a global current-operation pointer.
**Tech stack:** Bun 1.2.23, root-catalog Zod 4 and MCP SDK, installed Codex.

## Constraints

- All experiment code lives in `spikes/adr-0008-tool-execution/`.
- No production imports, new dependencies, global Codex configuration changes,
  raw checked-in traces, or supported API claims.
- The existing app-server transport may be reused from the ADR 0007 spike.
- Work in the current checkout alongside the existing Proposed ADR draft.
- No acceptance or commit is inferred from a passing spike.

## Steps

- [x] Read accepted capability boundaries, agreed ADR 0008 behaviour, area
  guidance, existing spike transport, and installed-version Codex metadata code.
- [x] Write the working contract before implementing it.
- [x] Define `contract.ts`, then create `conformance.ts` and `gateway.test.ts`.
  Factories inject tool definitions, a policy binding, and evidence acknowledgement.
  Use controlled promises to reproduce revocation during acknowledgement and
  cancellation after an observable effect; avoid timing-only assertions.
- [x] Run the conformance cases against a minimal non-working gateway and
  observe failures; implement `gateway.ts` and make them pass.
- [x] Implement `codex-binding.ts` and `mcp-server.ts` against tests for malformed
  metadata, exact thread/turn matching, closed bindings, and result projection.
- [x] Add `run-live.ts`, with cleanup covering every step after `mkdtemp`.
  Launch an isolated app-server and fixed stdio MCP catalogue. Bind accepted
  turns from the trusted client; verify word count and result correlation,
  then delay/replay operation-A traffic while B is allowed and require denial.
- [x] Add `spike:adr-0008`, run the canonical gate and live command, inspect
  failures, and record the actual result in indexed knowledge evidence.
- [x] Update the ADR's verification status and spike/design indexes, inspect
  the final diff, and report acceptance readiness and limitations.

The live metadata assumption is a gate. If it fails, report the incompatibility;
do not substitute model arguments or arrival-time inference for trusted origin.

## Outcome

The metadata gate and focused live proof passed. The offline conformance and
repository gate passed. A read-only review found no authority or execution
defect; its failure-output redaction finding was fixed with regression coverage.
The live runner also verifies the actual paired execution-evidence records.
Durable conclusions and reproduction commands live in the indexed
[evidence record](../../knowledge/evidence/adr-0008-tool-execution.md).
After reviewing the proof, the maintainer explicitly accepted ADR 0008 and
requested one cohesive commit of the decision and retained proof on 2026-09-04.
