# Documentation

Start with the [README](../README.md) for what Drawloom does, then
[Architecture](../ARCHITECTURE.md) for its principles and capabilities.

## What would you like to do?

- **Run Drawloom:** Follow the [desktop guide](../apps/desktop/README.md).
- **Build a workbench:** Start with [plugin packages](reference/plugin-packages.md),
  then read how the [desktop host](design/desktop-host.md) connects them.
- **Use or replace a capability:** Find its interface in the
  [foundation API guide](reference/foundation-api.md) and its implementation in
  [packages](../packages/README.md).
- **Understand the code:** Follow the
  [repository walkthrough](reference/repository-audit/README.md).
- **Contribute a change:** Read [Contributing](../CONTRIBUTING.md).
- **Report a security issue:** Use the private contact in
  [Security](../SECURITY.md), not a public issue.

## How the documents fit together

[Design guides](design/README.md) explain how the main systems work.
[Technical references](reference/README.md) provide API and operational details.
Each guide links to the relevant [architecture decision records](adr/), which
explain why an approach was chosen and what alternatives were considered.

[Plans](plans/README.md) describe particular pieces of work; they are not the
current API reference. [Security design](security/README.md) covers threats and
protections. [Knowledge records](../knowledge/) retain research and test evidence
with their sources and dates.

Use [DESIGN.md](../DESIGN.md) for the product's visual style and writing voice.
Keep each fact in one place and link to it from the other guides.
