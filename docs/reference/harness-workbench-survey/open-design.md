# Open Design: rich workbench survey

Read alongside the [survey scope and freshness record](README.md). [Open the architecture map](open-design.html).

Open Design is useful as a demanding consumer: it joins conversation, direct editing, files, previews, native agent sessions, plugins, media work and delivery. It is not a neutral specification for the host it would need.

## Provider boundary: concrete, not inferred

The Codex path uses `initialize`, `thread/start` or `thread/resume`, `turn/start`, and interruption. It runs with approvals disabled, explicitly rejects server-to-client requests, and closes stdin after turn completion. Its existing event normalizer remains the application seam. [Session implementation](https://github.com/nexu-io/open-design/blob/81044a03ca717f77a5bde38947903a8ef222da8c/apps/daemon/src/agent-protocol/codex-app-server/session.ts#L200).

This demonstrates **one selected App Server subset**, not full protocol parity. Its question-form UI does not contradict the absence of native approval/elicitation handling. The Claude integration is the **CLI**, while [this other provider](https://github.com/nexu-io/open-design/blob/81044a03ca717f77a5bde38947903a8ef222da8c/apps/web/src/providers/anthropic.ts#L10) uses the ordinary Anthropic API.

Drawloom must preserve these distinctions when comparing adapters. Merely choosing the same integration product does not establish identical host capabilities.

## Three flows

1. **Author:** project request → claim physical run → select provider transport → start/resume native session → stream normalized events → reconcile output files → capture historical evidence → finish run.
2. **Revise:** inspect file → edit through supported renderer → settle pending edits → create HTML checkpoint → review or export a selected version.
3. **Schedule:** compute occurrence → claim durable schedule slot → prepare ordinary run → execute → retain outcome. A losing claim must not expose a phantom conversation.

## What belongs to the workbench

Design directions, prompt composition, brand/craft rules, acceptance stages, export styling, retention policy, marketplace tiers, and unattended-work instructions remain consumer choices.

Candidate host obligations are narrower: stable resource identity, an honest runtime capability surface, bounded resource access, recoverable operations, scoped tool calls and standard UI communication. This survey does not prove that MCP Apps is insufficient for those obligations. Exercise the private video workbench before proposing an extension.

OD Next is conditional rather than universally active: its rollout checks task, runtime, bundled identity, verification and production approval. [source](https://github.com/nexu-io/open-design/blob/81044a03ca717f77a5bde38947903a8ef222da8c/apps/daemon/src/strategies/od-next/rollout.ts#L164). Neither large code volume nor a happy-path pipeline is evidence of mature acceptance safeguards.
