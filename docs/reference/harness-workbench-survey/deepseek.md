# DeepSeek Harness: host and runtime survey

Read alongside the [survey scope and freshness record](README.md). These are source-inspected capabilities at the recorded revision, not live compatibility or security certifications.

[Open the architecture map](deepseek.html). Its boxes are logical groups, not processes. The map is deliberately smaller than the inventory below.

## Composition matters

DeepSeek implements its own agent runtime as well as a host. The base bundle mounts registries, persistence, model adapters and orchestration facilities. The Web overlay disables many base tool/prompt consumers and mounts standing agent presets instead. Reading a package manifest or the base profile alone would give an inaccurate picture of the Web application. [Web overrides](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/packages/bundle/web-app/cordis.patch.yml#L351); [preset composition](https://github.com/deepseek-ai/deepseek-harness/blob/b2e3b2a0125854567a4a5fcba75782e42fe84901/packages/bundle/web-app/cordis.patch.yml#L474).

“Shipped” below means included in the inspected base/Web composition, possibly through a preset. It does not mean every provider is configured, every feature is enabled, or that we ran it.

## Three flows to study, not replicate wholesale

1. **Input to effect:** accept input → prepare provider request → log reconstructable facts → checkpoint → stream transient progress → settle durable result → checkpoint tool call before execution.
2. **Reconnect to reading:** retain visible window → reopen journal → recover missing durable entries → publish a consistent window → continue live notifications. Older history loads separately.
3. **File to deliverable:** write file → explicitly present it → append delivery event → open current path. None of these steps establishes human acceptance or preserves historical bytes.

These flows explain why “session storage” is not one concern. The runtime owns transcript truth. The host can own efficient UI projections. Storage of media bytes and curation of reusable knowledge remain distinct.

## What transfers to Drawloom

Use these as questions and acceptance scenarios: bounded reading, stable identity, gap recovery, lifecycle cleanup, explicit effect uncertainty, provider support reporting and artifact provenance.

Do not import Cordis, its dynamic client kernel, a second LLM loop, goal/workflow machinery or its session format simply to match feature count. Our selected external runtime remains responsible for its transcript, compaction and native execution. An implementation detail becomes a public contract only after a real consumer and an approved boundary decision require it.
